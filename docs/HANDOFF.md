## 2026-11-26 실물 실패 보고

사용자가 움직임 판정 및 모양 학습이 제대로 진행되지 않는다고 보고했다.
새 진단 기능의 실물 성공으로 기록하지 않는다. 색 문제를 센서 한계로 추정했으나 원인은 미확정이다.
현재 방향·모양은 같은 16×16 배경 분리에 의존한다. 먼저 DIP2 실루엣 상태,
TARGET 값, B 조작 후 TAUGHT 변화, MOVE/SHAPE 문구를 구분해 확인한다.
모양 등록은 한 장의 고정 위치 템플릿 저장이며 위치·크기 정규화가 없다.
방향은 규칙 기반이며 학습하지 않는다. MOVE/SHAPE는 진단 표시로만 연결돼 있다.
이 보고를 반영한 RTL 변경·재빌드는 아직 수행하지 않았다.

## 최신 후속 구현: 색·방향·모양 시험 화면

여러 색 이름, 배경 분리 물체의 이동 방향, 직접 등록한 세 가위바위보 실루엣을
문자로 출력하는 시험 화면을 구현했다. 조작과 한계는 [VISION_LAB.md](VISION_LAB.md) 참조.
진입: DIP3·4 ON, DIP1·2·5 OFF. A=등록할 이름 선택, B=등록, C=빈 배경 등록.
배경 등록은 세 템플릿을 지운다. DIP2는 분리 실루엣 표시다.
임의 물체 인식이 아니며, 위치·크기 고정 조건의 템플릿 비교다. 실물 정확도는 미확인이다.
후속 BIT 경로는 `board/vision_lab/usagi_vision_lab.bit`이며 이전 진단 BIT와 구분한다.
생성 완료. 분석기·카메라 시뮬레이션 통과, 배선 후 WNS +0.620ns / WHS +0.054ns,
DRC 오류 0(경고 있음, VISION_LAB 참조). 소스 해시와 BIT 해시를 해당 출력 폴더에 기록했다.
보드 다운로드와 새 인식 기능의 실물 검증은 아직 실행하지 않았다.
아래의 이전 "미구현" 표기는 당시 확인 시점의 기록으로 읽는다.

## 가장 중요한 확정 사항: 주클록 핀은 B6

**현재 실물 보드의 `MAIN_CLOCK1`은 B6를 사용한다. G2로 되돌리지 않는다.**
사용자가 같은 보드에서 B6로 변경한 후 동작한다고 확인했다.

```tcl
set_property PACKAGE_PIN B6 [get_ports MAIN_CLOCK1]
set_property IOSTANDARD LVCMOS33 [get_ports MAIN_CLOCK1]
create_clock -name main_clock -period 20.000 [get_ports MAIN_CLOCK1]
```

- 활성 제약: `../final.srcs/constrs_1/new/hanback_lcd_pet.xdc`.
- 보드 CLOCK SELECT는 **F / 50MHz**. 숫자 50뿐 아니라 MHz 단위 LED도 사용자 확인 완료.
- 강의 PDF p.5에는 G2라고 되어 있지만 실제 보드에서 G2 설정은 흰 화면·LED 무반응을 보였다.
  B6로 변경하자 동작했다. **현재 보드에서는 실물 확인 결과가 우선이다.**
- 자료와 실물의 차이가 생긴 보드/모듈 리비전 등의 정확한 이유는 아직 확정하지 않았다.
  자료에 적혀 있다는 이유로 G2를 다시 적용하거나, FPGA 패키지 핀 존재만으로 연결을 추정하지 않는다.
- 기존 G2 기준 DRC·타이밍 통과는 실물 클록 연결이 맞다는 증거가 아니었다.
- 현재 XDC의 기존 클록 배선 허용 설정은 유지했다. B6에서의 필요성은 별도 검토 대상이며,
  인수인계 문서 정리 중에는 변경하지 않았다.

## 프로젝트 목적과 현재 범위

디지털시스템 기말고사 대체 프로젝트다. FPGA에서 카메라로 색 카드를 보고
LCD의 우사기가 반응하며, 카드와 먹이의 연관을 뉴런/시냅스 회로로 학습하는 것이 핵심이다.
우사기 외형은 사용자가 제공한 참고 이미지의 긴 귀, 노란 몸, 눈썹·볼·입 특징을 반영했다.

현재 구현 범위는 두 경로다.

1. OV7670 영상 → 중앙 노란 카드 검출 → LCD 미리보기와 우사기 표정 반응.
2. 카드/먹이 자극 → Izhikevich 고정소수점 뉴런 3개와 시냅스 연합 학습 → 기대 반응.

일반적인 얼굴·사물·사진 내용 인식, 자유 자세의 손 인식, 춤 등은 구현 완료 기능이 아니다.
후속 진단 화면에는 배경 분리 물체의 방향과 고정 위치·크기 조건의 가위바위보 템플릿 비교가 추가됐다.
이 진단 기능을 일반 물체 인식이나 실물 정확도 검증 완료로 해석하지 않는다.
`PROJECT_PLAN.md`는 초기의 넓은 아이디어 기록이므로 구현 완료 목록으로 읽지 않는다.

## Vivado 소스 누락으로 합성 실패했던 문제

증상: `module 'ov7670_config' not found`, Sources에 카메라 모듈이 `?`로 표시됨.
파일은 디스크에 있었지만 현재 열린 GUI의 합성 소스 목록에 새 모듈이 빠져 있었다.

현재 `final` 프로젝트의 Tcl Console에서 실행한다.

```tcl
source {C:/Users/sodas/.Xilinx/final/scripts/register_project.tcl}
```

`ov7670_config`, `camera_pipeline`, `sccb_master`의 등록·합성 사용 상태를 확인하는
메시지가 나온다. Sources의 `?` 해소 후 필요 시 Reset Run → Run Synthesis를 진행한다.
`.sv`는 정상적인 SystemVerilog 형식이다. 파일 위치를 다시 옮기거나 복제해서 해결하지 않는다.
실행 중인 GUI는 외부 `.xpr` 변경을 자동으로 반영하지 않으며, GUI 저장으로 이전 목록이
다시 기록될 수 있다. **다른 Vivado 프로세스에서 같은 프로젝트를 동시에 저장·빌드하지 않는다.**

## 실물 조작과 카메라 확인

1. CLOCK SELECT F=50MHz, B6 XDC로 만든 BIT를 다운로드한다.
2. 직접 카메라 반응은 **DIP4 ON, DIP1·2·3·5 OFF**. H를 눌렀다 놓고 잠시 기다린다.
3. LCD 왼쪽 영상의 노란 ROI 사각형에 노란 카드를 보여 준다.
   VGA 640x480 중앙 320x240 영역에서 노란 픽셀 35% 이상이 3프레임 유지되면 감지한다.
   해제는 20% 미만 3프레임, 영상 중단은 약 1초 후 인식을 해제한다.
4. DIP5 ON은 **OV7670 센서 내부 컬러바**. OFF로 돌리면 실제 영상으로 재초기화한다.
   컬러바를 실제 촬영이나 카드 인식 성공으로 기록하지 않는다.
5. 카메라 학습은 DIP1·2·4 ON, DIP3·5 OFF. 카드 제시와 B 먹이를 짝짓고,
   DIP2 OFF 후 카드만으로 기대 반응을 비교한다. H는 학습값도 지운다.

| 조작 | 역할 |
|---|---|
| DIP1 | 직접 표정 / 뉴런 반응 모드 |
| DIP2 | 뉴런 모드 학습 허용. 직접 카메라 모드에서는 노란 픽셀 강조 / 진단 패널에서는 실루엣 표시 |
| DIP3 | 뉴런 모드 ROM 자동 자극 우선. 직접 카메라 모드에서는 새 진단 패널 진입 |
| DIP4 | A 대신 카메라 카드 입력, 미리보기 표시 |
| DIP5 | 센서 내부 컬러바; 변경 시 카메라 재초기화 |
| A / B / C | 일반 모드: 수동 카드 / 먹이 / 대조 자극. 진단 패널: 이름 선택 / 템플릿 등록 / 빈 배경 등록 |
| H | 클록·화면·카메라·학습 전체 초기화 |

OV7670 ID는 `0x7673`, SCCB 읽기/쓰기 주소는 `0x43/0x42`다.
핀 전체와 설정 근거는 [CAMERA_OV7670.md](CAMERA_OV7670.md)에 있다.
미리보기는 160x120 이중 BRAM 버퍼를 화면에서 320x240으로 확대한다.

## LED 진단 변경과 동시 작업 주의

흰 화면·LED 무반응을 조사하며 `board_clocks.sv`와 `usagi_board_top.sv`에
MMCM lock 이전에도 관찰할 수 있는 LED 진단을 추가했다. 현재 디스크 소스 기준:

| LED | 의미 |
|---|---|
| LED1 / bit0 | MMCM lock |
| LED2 / bit1 | B6 원래 입력 클록 카운터의 점멸. H로 초기화하지 않음 |
| LED3 / bit2 | 선택된 카드 입력 |
| LED4 / bit3 | 센서 설정 완료 |
| LED5 / bit4 | 센서 설정 오류 |
| LED6 / bit5 | A 버튼 원신호 |
| LED7 / bit6 | H 버튼 원신호 |
| LED8 / bit7 | 항상 ON인 다운로드 이미지 표식 |

위 변경과 사용자의 B6 수정이 겹쳐 에이전트 배치 빌드는 중단했다.
사용자 GUI 빌드는 종료하지 않았다. 중단된 `board/results/build.log`의 실패는
이 취소 과정의 기록일 수 있으며, 그 자체로 RTL 오류라고 판단하지 않는다.
어느 소스 버전이 사용자의 당시 BIT에 포함됐는지는 빌드가 파일을 읽은 시점에 달려 있다.
현재 소스를 다시 빌드할 경우 위 LED 표가 적용된다.

  확인 전에 핀이나 대규모 구조를 다시 바꾸지 않는다.
