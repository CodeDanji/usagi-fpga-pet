# 우사기 FPGA 가상 생물 프로젝트 정리

> 최신 구현·실물 결과는 [인수인계서](HANDOFF.md)를 먼저 확인한다.
> **현재 보드 주클록은 B6이며, G2 설정으로 되돌리지 않는다.** 아래 내용은 초기 기획이다.

- 정리일: 2026-11-18
- 목적: 지금까지의 아이디어, 기술 검토, 구현 후보와 우선순위를 기록한다.
- 문서 상태: 구현 전 기획·검토 정리. 아래의 권장 구조와 일정은 제안이며, 실제 보드에서 검증된 사양이나 구현 결과가 아니다.

## 1. 프로젝트 개요

Xilinx FPGA와 CMOS 이미지 센서를 이용해 주변을 보고 반응하고, 일부 자극을 학습하는 가상 생물 ‘우사기’를 만든다. Talking Tom처럼 LCD 속 아바타가 사람의 행동에 표정·동작·소리로 반응하는 경험을 목표로 한다.

사용자가 제공한 우사기 참고 이미지를 바탕으로 눈·귀·팔·몸의 변화가 잘 드러나는 애니메이션을 구성한다. 특정 유명 랩 동작도 놀이 요소로 고려했으나, 정확한 동작·음원은 아직 정하지 않았다.

핵심 경험은 다음과 같다.

1. 카메라로 손과 색 카드를 관찰한다.
2. 쓰다듬기, 툭 치기, 인사 등 방향 제스처에 반응한다.
3. 색 카드와 먹이를 연관 지어 조건반사를 학습한다.
4. 가위바위보 손 모양을 학습·인식하고 대결한다.
5. 버튼으로 랩·춤을 실행하고, 반복 자극에는 반응 정도가 달라진다.

## 2. 목표와 제약

### 사용자가 제시한 방향

- PC·마우스를 이용한 실행 중 입력 대신 보드의 카메라·버튼·스위치를 활용한다.
- 뉴런 모방과 학습을 기술적 중심으로 고려한다.
- 관객이 직접 참여하고 즉시 반응을 볼 수 있어야 한다.
- 학술적으로 설명할 원리와 측정 가능한 평가 항목이 있어야 한다.
- 제출까지 약 1개월이지만, 약 2주 안에 주요 기능을 마무리하는 것을 희망한다. 수업 기준 약 2회이다.

### 현재 파악한 장비

- 제조사: Hanback Electronics(한백전자).
- 보드에 적힌 명칭: 사용자가 ‘HPE-FPGA Digital’, ‘FPGA/SoC’로 전달.
- 사용 FPGA 방향: Xilinx.
- 활용 예정 주변장치: TFT LCD, CMOS 이미지 센서, 버튼·스위치 등.
- 정확한 FPGA 부품 번호, 보드 리비전, 센서 모델과 메모리 구성은 미확인.

한백의 FPGA Digital Logic Design 공식 자료에는 모듈형 FPGA, TFT LCD, CMOS 이미지 센서, 오디오 블록과 SD 소켓 등이 소개되어 있다. 다만 해당 자료의 구성이 실제 사용 보드와 일치하는지는 확인해야 한다.

‘보드 자체 동작’은 우선 실행 중 PC가 필요 없는 구성을 뜻한다. FPGA 합성·다운로드·개발 중 검증에 PC를 사용하는 것과는 구분한다. 전원을 껐다 켜도 자동 시작하거나 학습값을 유지하려면 비휘발성 저장 구성이 추가로 필요하다.

## 3. 기능과 학습의 구분

| 기능 | 처리 대상 | 학습 여부 | 권장 위치 |
|---|---|---|---|
| 우사기 애니메이션 | 표정·자세·비트 | 기본적으로 없음 | 스프라이트 출력·상태기계 |
| 색 카드 검출 | 색상·영역 면적 | 초기에는 규칙 기반 | 영상 전처리 |
| 방향 제스처 | 손 위치·속도·이동 방향 | 초기에는 규칙 기반 | 추적·이벤트 검출 |
| 손 모양 인식 | 가위·바위·보 영상 특징 | 정답을 주는 지도학습 | 소형 분류기 |
| 이기는 패 선택 | 인식한 상대 패 | 고정 규칙이면 없음 | 게임 로직 |
| 대응 행동 학습 | 상대 패와 승패 보상 | 보상 학습 | 소형 평가값 테이블 등 |
| 상대 습관 학습 | 이전 패·승패 기록 | 통계 또는 예측 학습 | 선택적 확장 |
| 조건반사 | 색 신호와 먹이의 시간 관계 | 시냅스 연합 학습 | 뉴런·학습 회로 |
| 반복 자극 적응 | 자극의 지속·반복 | 내부 상태 변화 또는 별도 습관화 규칙 | 뉴런 또는 행동 모델 |

모든 기능을 뉴런으로 처리할 필요는 없다. 영상 수신·LCD 출력은 일반 디지털 회로, 조건반사는 뉴런과 시냅스, 게임 진행과 모드 전환은 상태기계로 구성하는 방안을 권장한다.

## 4. 전체 구현 구조 제안

```text
CMOS 이미지 센서
    ↓
센서 설정·영상 수신·픽셀 좌표 생성
    ↓
관심 영역 선택·밝기/색 처리·축소
    ├─ 색 카드 검출 ─────────→ 조건반사 뉴런·시냅스 학습
    ├─ 손 중심·이동 추적 ────→ 방향 제스처·반복 자극 처리
    └─ 손 모양 특징 추출 ────→ 가위바위보 분류·학습·대결
                                      ↓
버튼·스위치 ──────────────────→ 모드·행동 상태 결정
                                      ↓
                              LCD 스프라이트·음향
                                      ↓
                              선택형 진단 화면
```

영상 전처리는 여러 기능에서 공유한다. 원본 고해상도 영상 전체를 뉴런마다 입력하기보다, 작은 관심 영역과 특징값을 이용해 연산·메모리 부담을 줄인다.

## 5. CMOS 이미지 센서 사용

센서는 각 픽셀에 들어온 빛을 디지털 값으로 변환해 연속 프레임으로 전달한다. FPGA는 사진 파일이 아니라 픽셀 스트림을 받아 처리할 수 있다.

- 실제 출력은 RAW Bayer, RGB 또는 YUV/YCbCr 등일 수 있으며 센서 모델·설정에 따라 다르다.
- 병렬 인터페이스라면 데이터, 픽셀 클록, 줄·프레임 구분 신호 등을 사용한다. 실제 핀과 타이밍은 매뉴얼 기준으로 확정한다.
- 센서 초기 설정과 영상 수신 회로가 필요하다.
- 연속 인식과 연속 학습을 분리한다. 평소에는 인식하고, 학습 모드나 정답 버튼 입력 때만 가중치를 갱신하는 방안이 적합하다.
- 단안 카메라로 실제 접촉이나 충격의 크기를 직접 측정하는 것은 아니다.

초기 환경은 카메라 고정, 일정한 배경·조명, 지정된 손 입력 영역으로 제한한다. 위치 안내와 간단한 밝기·배경 보정 기능을 검토한다.

## 6. 가위바위보

### 6.1 손 모양을 보드에서 학습

```text
손 제시 → 영역 추출 → 특징 계산 → 정답 버튼 → 분류기 가중치 갱신
```

- 학습 모드에서 가위·바위·보 정답을 버튼으로 제공한다.
- 특징 후보는 축소한 흑백 격자, 구역별 손 면적, 가로·세로 픽셀 분포 등이다.
- 소형 퍼셉트론 등의 학습 가능한 분류기를 구현 후보로 둔다. 최종 알고리즘은 실제 영상으로 비교 후 결정한다.
- 동일한 사진만 반복하지 않고, 위치·모양이 조금 다른 예시를 수집한다.
- 시험에서는 가중치를 고정하고 학습에 사용하지 않은 예시를 평가한다.
- 분류가 모호하거나 손이 움직이는 중이면 판정을 보류한다. 여러 프레임의 일관성과 점수 차이를 이용할 수 있다.

퍼셉트론으로 구현한 손 모양 학습과 Izhikevich 뉴런 모방은 서로 다른 부분이다. 전자를 스파이킹 신경망으로 바꾸는 것은 추가 연구 범위이다.

### 6.2 빠르게 보고 이기는 후출 모드

```text
상대 손 인식 → 가위에는 바위, 바위에는 보, 보에는 가위 → LCD 출력
```

- 사용자가 원하는 ‘빠르게 반응해 이기는’ 시연 모드이다.
- 손 모양을 학습하는 부분과 승리 패를 선택하는 규칙을 구분한다.
- 정확히 인식했고 상대가 손을 유지한다는 조건에서 이기는 패를 낸다.
- 영상 오인식과 지연 때문에 시스템 전체의 무조건 승리를 보장하지 않는다.
- 센서 프레임 수신부터 LCD 결과 표시까지의 지연을 측정한다.

### 6.3 승패 보상으로 대응 행동 학습

작은 구현 후보는 상대 패 3개 × 우사기 행동 3개의 평가값 9개를 저장하는 방식이다.

```text
인식한 상대 패 s → 행동 a 탐색·선택 → 승패 보상 r → Q(s,a) 갱신
```

예시 갱신식:

```text
Q(s,a) ← Q(s,a) + α × [r − Q(s,a)]
승리: +1 / 무승부: 0 / 패배: −1
```

- 초기에는 여러 행동을 시도하고, 학습 후 평가가 높은 행동을 더 자주 선택한다.
- 상대 패를 이미 본 뒤 선택하는 설정에서는 대응 관계를 학습하는 것이다.
- 위 식은 한 단계 보상 평가의 간단한 구현안이며, Izhikevich 또는 STDP 학습은 아니다.
- 초기 검증은 정답으로 확인된 상대 패를 사용해 인식 오류와 행동 학습 오류를 분리한다.
- 승패로 보상을 자동 생성하는 방식과 사람이 보상·벌 버튼을 누르는 방식은 평가에서 구분한다.

### 6.4 동시 대결과 상대 습관 학습

- 공정한 동시 대결 모드에서는 현재 상대 손을 읽기 전에 우사기 선택을 확정한다.
- 과거 선택의 빈도나 전이 패턴으로 다음 패를 예측하는 확장을 고려한다.
- 상대가 독립적으로 균등 무작위 선택을 하면 과거 기록만으로 지속적인 승률 우위를 얻을 수 없다.
- 후출 모드와 동시 대결 모드는 화면에서 명확히 구분한다.

### 6.5 보상 기반 스파이킹 학습 확장

입력 특징을 스파이크로 변환하고, 행동 뉴런과 연결 가중치를 보상 조절 STDP 등으로 학습하는 방식도 가능하다. 그러나 탐색, 선택에 기여한 연결의 추적, 지연 보상, 가중치 안정화가 필요하다. 2주 핵심 범위보다 도전 기능으로 분류한다.

## 7. 색 카드 기반 파블로프 조건반사

### 시연 시나리오

1. 학습 전에는 노란 카드에 특별히 반응하지 않는다.
2. 먹이 버튼을 누르면 실제 먹이 제공 동작과 기쁨 반응이 발생한다.
3. 노란 카드를 보여준 뒤 먹이 버튼을 누르는 경험을 반복한다.
4. 이후 노란 카드만으로 먹이를 기대하는 반응이 발생한다.
5. 학습하지 않은 다른 색 카드에는 같은 반응이 나타나지 않는지 비교한다.

기대 반응과 실제 섭취를 분리한다. 카드만 봤다고 배부름 상태까지 증가시키지는 않는다.

### 회로 구성 후보

```text
색 카드 → 감각 뉴런 ── 학습 가능한 시냅스 ──→ 기대 반응 뉴런
                                                    ↑
먹이 버튼 ─────────────── 강한 교사 입력 ─────────────┘
```

- 뉴런 코어: Izhikevich 모델로 막전위와 회복 변수, 스파이크를 계산한다.
- 학습 회로: 자극의 시간 관계에 따라 시냅스 가중치를 갱신한다.
- 감각 입력을 내부 스파이크 열로 변환하고 학습 시간창을 정한다.
- 사람의 카드·버튼 조작 시간과 내부 뉴런 시간의 대응을 명시한다.
- 가중치 상·하한, 시험 시 학습 중지, 초기화 기능을 둔다.
- STDP를 추가하는 것만으로 조건반사가 자동 성립하는 것은 아니다. 연결 구조와 시간 관계를 기준 모델에서 검증해야 한다.

확장으로 소거와 재학습을 고려한다. 보상 없이 카드만 반복했을 때 반응을 약화하려면 별도의 약화·학습 규칙이 필요하다.

## 8. Izhikevich 뉴런 코어

상태 변수는 막전위 v와 회복 변수 u이다. 입력 I에는 외부 자극과 시냅스 입력이 반영된다.

```text
dv/dt = 0.04v² + 5v + 140 − u + I
du/dt = a(bv − u)

v ≥ 30에 도달하면:
  spike 발생
  v ← c
  u ← u + d
```

- a, b, c, d는 뉴런의 동작 특성을 설정하는 파라미터이다.
- v, u의 변화는 뉴런의 동작이고, 시냅스 가중치 갱신은 학습이다.
- 30은 스파이크 꼭대기를 검출·리셋하는 기준이며, 생물학적 발화 시작 문턱을 그대로 뜻하지 않는다.
- FPGA에서는 이산 시간 수치 적분과 고정소수점 연산을 구현한다.
- 시간 간격, 비트 수, 갱신 순서, 발화 검출·리셋 순서를 소프트웨어 기준 모델과 일치시켜야 한다.
- 뉴런의 시뮬레이션 시간 간격과 FPGA 하드웨어 클록은 별개이다.

한 코어를 여러 뉴런 상태에 시간 분할해 사용하는 방식과 뉴런별 연산 회로를 두는 방식을 자원에 따라 검토한다. 구체적인 뉴런 수와 숫자 형식은 아직 확정하지 않았다.

## 9. 좌우상하 제스처

손 영역의 중심 위치를 추적해 이동량과 속도를 계산한다.

```text
Δx = x(t) − x(t−1)
Δy = y(t) − y(t−1)
```

| 조건 후보 | 해석 | 반응 |
|---|---|---|
| 머리 영역에서 느린 좌우 왕복 | 쓰다듬기 | 눈 감기·기쁨 |
| 옆 영역에서 좌우 왕복 | 인사 | 손 흔들기 |
| 위에서 아래로 빠른 이동 | 툭 치기 | 놀람·몸 찌그러짐 |
| 아래에서 위로 이동 | 들어 올리기 제스처 | 점프 |

- 방향뿐 아니라 시작 위치, 이동 거리, 속도, 반복을 함께 사용한다.
- 작은 흔들림은 무시하고, 이벤트 뒤 재인식 대기 시간을 둔다.
- 손이 사라지면 추적 상태를 초기화한다.
- 대각선·영역 경계에서 우선순위를 정한다.
- 실제 접촉을 측정한 것으로 표현하지 않는다.

## 10. 반복 자극 적응·습관화

### 뉴런 수준 단기 적응

지속·반복 자극에서 회복 변수 u의 영향으로 발화가 감소하는지 검증하고, 발화 정도를 우사기의 반응 크기와 연결한다. 효과는 자극 간격과 뉴런 파라미터에 따라 달라진다.

### 행동 수준 습관화

같은 자극이 반복되면 습관화 상태를 높여 반응을 줄이고, 자극이 없으면 서서히 회복시킨다.

```text
처음 자극: 큰 반응 → 반복 자극: 작은 반응 → 휴식 후: 반응 회복
```

별도 상태값으로 구현한 습관화는 시냅스 학습과 구분해 설명한다. 초기에는 행동 모델을 완성하고, 뉴런 적응으로 구동하는 버전과 비교할 수 있다.

## 11. LCD·음향과 행동 제어

### 기본 애니메이션

대기, 눈 깜빡임, 기쁨, 놀람, 먹이 기대, 먹기, 가위바위보, 랩·춤 등의 상태를 스프라이트로 표시한다. 최종 종류·개수·크기는 메모리 예산에 맞춰 정한다.

픽셀 데이터만 계산할 때, 96×96 크기 4비트 스프라이트 20장은 92,160바이트, 약 90KiB이다. 팔레트·메타데이터·LCD 버퍼는 별도이며, 투명색 처리와 프레임버퍼 사용 여부도 결정해야 한다.

### 랩·춤

- 버튼으로 시작하고 비트에 맞춰 몸·팔·입 모양을 바꾼다.
- 리듬 버튼 입력에 따라 반응을 달리하는 확장을 고려한다.
- 피에조 박자 출력과 실제 음성·음원 재생은 별개이다.
- 실제 랩 음성은 오디오 인터페이스, 샘플 저장과 재생 경로가 확인된 뒤 추가한다.

### 모드 분리

| 모드 | 활성 입력 |
|---|---|
| 평상시 | 시선 추적·쓰다듬기·인사 |
| 조건반사 학습 | 색 카드·먹이 버튼 |
| 가위바위보 학습 | 손 모양·정답 버튼 |
| 가위바위보 대결 | 손 모양·게임 진행 |
| 랩·춤 | 리듬·시작·정지 버튼 |

모드 간 우선순위와 전환 시 초기화 규칙을 둬, 게임 중 손동작을 때림으로 오인하는 등의 충돌을 막는다.

## 12. 추가 아이디어

- **시선 추적:** 손 위치에 따라 눈동자나 고개가 움직인다. 입력 검출 여부도 자연스럽게 전달한다.
- **뇌 관찰 화면:** 버튼으로 막전위, 스파이크, 연결 가중치, 현재 인식 상태를 표시한다.
- **소거·재학습:** 색 신호와 보상의 관계를 바꾸며 반응 변화를 비교한다. 추가 학습 규칙이 필요하다.
- **상대 습관 적응:** 가위바위보에서 자주 내는 패와 패턴을 학습한다.

위 기능은 추가 후보이며 모두 구현하기로 확정한 것은 아니다.

## 13. 권장 우선순위와 2주 일정

### 범위 제안

1. 핵심: 카메라·LCD 안정화, 기본 우사기, 색 검출, Izhikevich 코어와 조건반사.
2. 시연 강화: 좌우상하 제스처, 반복 자극 반응, 버튼 춤·비트.
3. 도전: 손 모양 학습·인식과 후출 대응.
4. 추가 도전: 가위바위보 보상 학습, 실제 랩 음성, 소거·재학습.

가위바위보 손 모양 학습은 사용자가 원하는 주요 기능이다. 다만 조건반사와 동시에 새로 구현할 때 일정 위험이 커서, 초기 통합 결과에 따라 우선순위를 다시 정해야 한다.

### 일정 초안

수업 외 개발·시뮬레이션과 보드 검증 기회가 있다는 가정이다. 실제 보드 접근이 수업 두 번뿐이면 전체 기능을 약속하기 어렵다.

| 기간 | 목표 | 확인할 결과 |
|---|---|---|
| 1~3일 | 제공 예제로 카메라·LCD, 우사기 출력 | 실제 영상·화면 안정 동작 |
| 4~6일 | 색 검출, 손 위치·방향 추적 | 검출 상태를 화면에서 확인 |
| 7~9일 | 조건반사 뉴런과 행동 통합 | 학습 전후·대조 자극 차이 |
| 10~11일 | 가위바위보 분류·학습·대응 | 미사용 예시의 인식 결과 |
| 12~14일 | 모드 통합, 반복 시험, 시연 준비 | 기능 간 충돌 없이 동작 |

카메라·LCD 예제가 없거나 초반 연동이 늦어지면, 기능을 추가하기 전에 범위를 조정한다. AI 코드 생성 속도와 실제 핀·클록·센서·메모리 검증 시간은 별도로 잡는다.

## 14. 기술적 위험과 확인 사항

- [ ] FPGA 칩의 정확한 부품 번호와 사용 도구 버전 확인.
- [ ] 회로도·핀 제약 파일·보드 매뉴얼 확보.
- [ ] 카메라 센서 모델, 출력 형식·해상도·프레임률 확인.
- [ ] 실제 동작하는 카메라·LCD 예제 유무 확인.
- [ ] LCD 해상도·인터페이스·출력 타이밍 확인.
- [ ] 내부 BRAM과 외부 메모리 자원, 기존 제어기 유무 확인.
- [ ] 카메라·연산·LCD 간 클록 도메인 교차 설계 확인.
- [ ] 오디오 출력 경로와 실제 음성 재생 가능 여부 확인.
- [ ] 전원 재시작 후 FPGA 자동 구성·학습값 유지 필요 여부 결정.
- [ ] 팀원 수·역할·수업 외 보드 접근 가능 시간 확인.

클록 도메인이 다르면 동기화·비동기 FIFO 등의 구조와 타이밍 검토가 필요하다. 타이밍 경로를 예외 처리하는 것만으로 안전한 데이터 전달이 보장되지 않는다.

## 15. 평가·검증 계획

| 항목 | 평가 방법 |
|---|---|
| 카메라·LCD | 프레임 깨짐·멈춤·모드 전환 반복 확인 |
| 손 모양 | 학습과 분리한 시험 이미지·실사용 예시로 혼동행렬 측정 |
| 후출 대응 | 안정된 손 제시부터 우사기 응답까지 지연, 오인식 포함 승리율 |
| 보상 학습 | 학습 전후 행동 평가값·선택 분포 비교, 고정 규칙 기준과 비교 |
| 조건반사 | 학습 전후 반응률, 대조 색 오반응률, 가중치 변화 |
| 제스처 | 방향별 성공률과 비의도 동작의 오검출 |
| 반복 자극 | 반복 중 반응 감소와 휴식 후 회복 곡선 |
| 뉴런 코어 | 같은 수치 갱신 규칙의 소프트웨어 대비 파형·발화 시점 오차 |
| 하드웨어 | LUT·FF·DSP·BRAM 사용량, 타이밍 만족 여부 |

결과가 단순 규칙인지, 내부 상태 변화인지, 실제 가중치 학습인지 구분해 발표한다. 예상 성능을 검증된 결과처럼 쓰지 않는다.
