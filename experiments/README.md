# 우사기 FPGA: 구현 가능성 실험

기말고사 대체 프로젝트를 시작하기 위한 두 가지 실험의 설명이다.
현재는 소스를 `final.srcs`로 이동하고 `final.xpr`에 등록했다.
보드 다운로드와 현재 열린 Vivado 창 갱신은 [작업 폴더 설명서](../README.md)를 따른다.

이번 실행의 수치와 미검증 항목은 [검증 결과](results/VERIFICATION.md)에 기록했다.

1. 카메라의 색 카드 입력으로 LCD 속 우사기 표정이 바뀌는 경로.
2. 소수 뉴런과 학습 시냅스로 조건반사가 성립하는지 확인하는 경로.

손 추적, 가위바위보, 음성, 외부 메모리 제어기는 이 단계에 포함하지 않는다.

## 현재 가능한 실행과 한계

- Vivado 2024.2의 XSim으로 수신·색 검출·클록 간 전달·LCD·학습 회로를 시뮬레이션한다.
- `xc7s75fgga484-1` 대상으로 독립 합성해 자원과 합성 단계 타이밍을 확인한다.
- **실물 카메라/LCD 동작은 아직 검증하지 않았다.** LCD·버튼·학습용 다운로드 파일은 상위 폴더의 보드 프로젝트에서 별도로 만든다.
- 카메라 센서 모델·초기화 레지스터·핀맵, 실제 LCD 타이밍·클록 출력·I/O 전압이 필요하다.
- 센서 계약과 LCD 타이밍의 현재 값은 시험용 가정이다. 이를 실제 부품 사양처럼 사용하지 않는다.

## 실행

작업 폴더에서 PowerShell로 실행한다.

```powershell
# 시뮬레이션 세 개와 두 실험의 합성을 순차 실행
& ./experiments/scripts/run_checks.ps1 -Task all

# 원하는 부분만 실행
& ./experiments/scripts/run_checks.ps1 -Task card
& ./experiments/scripts/run_checks.ps1 -Task display
& ./experiments/scripts/run_checks.ps1 -Task conditioning
& ./experiments/scripts/run_checks.ps1 -Task synth-card
& ./experiments/scripts/run_checks.ps1 -Task synth-conditioning
```

스크립트의 기본 Vivado 경로는 `C:\Xilinx\Vivado\2024.2\bin\vivado.bat`이다.
Python은 현재 PC의 Codex 번들 경로를 기본값으로 사용한다. 다른 환경에서는
`-Vivado '경로' -Python 'Python3 실행파일 경로'`로 바꾼다.
학습 기준 모델은 Python 표준 라이브러리만 사용한다.
스프라이트 오프라인 생성에는 Pillow가 필요하며 현재 번들 Python에 포함돼 있다.

이 PC의 Vivado Tcl은 숨김 폴더가 들어간 현재 경로를 잘못 해석한다.
실행기는 비어 있는 U~Z 중 하나를 작업 폴더에 임시 `subst` 연결하고,
정상 종료·오류 모두에서 연결을 해제한다. 기존 드라이브 연결은 덮어쓰지 않는다.
설치 파일과 디렉터리 속성을 변경하지 않는다.
생성된 중간 `.xpr`에는 임시 드라이브 경로가 들어갈 수 있으므로, 반복 실행은 위 스크립트를 사용한다.
같은 `Task`를 동시에 두 번 실행하지 않는다.

실행 결과는 `results/`, 재생성 가능한 중간 프로젝트는 `build/`에 저장된다.
Vivado가 `$fatal` 후에도 종료 코드 0을 반환할 수 있어, 실행기는 로그의 오류와 PASS 표식까지 검사한다.

## 실험 1: 색 카드에 반응하는 우사기

```text
설정된 CMOS 센서 또는 가상 RGB565 센서
  -> parallel_rgb565_rx
  -> card_detector (중앙 ROI, 노란색 면적, 히스테리시스, 3프레임 안정화)
  -> cdc_mailbox (프레임 통계와 카드 상태만 전달)
  -> LCD 도메인의 입력 정지 감시
  -> usagi_display + lcd_timing
```

### 핵심 파일

아래 `rtl/`와 `rom/`는 현재 `final.srcs/sources_1/`을 기준으로 한다.
테스트벤치는 `final.srcs/sim_1/new/`에 있다.

| 파일 | 역할 |
|---|---|
| `rtl/vision/card_pet_top.sv` | 카메라부터 LCD RGB 출력까지 연결한 코어 |
| `rtl/vision/parallel_rgb565_rx.sv` | 8비트 병렬 입력을 RGB565 픽셀·좌표로 변환 |
| `rtl/vision/card_detector.sv` | ROI 색 검출과 프레임별 안정화 |
| `rtl/common/cdc_mailbox.sv` | 카메라·LCD 클록 사이의 데이터 전달 |
| `rtl/vision/synthetic_camera.sv` | 같은 수신 회로를 거치는 가상 센서 |
| `rtl/display/usagi_display.sv` | 우사기 2표정과 간단한 진단 표시 |
| `rtl/display/lcd_timing.sv` | 파라미터로 분리한 LCD 래스터 |
| `rom/usagi_128x128.mem` | 제공된 우사기 참고의 비율·눈썹·볼·입을 반영한 2표정 스프라이트 |

코어는 `cam_pclk`와 `lcd_pclk`를 각각 입력받는다. `reset`은 두 도메인에서 동시에
비동기 assertion되고, 각 도메인에서 동기적으로 해제된다. 리셋은 최소 몇 클록 이상 유지한다.
정지한 카메라 클록이 재개돼도 리셋 해제는 해당 클록에서 동기화된다.

`SYNTHETIC=1`은 기본값이며, 카메라 입력 포트 대신 가상 센서를 사용한다.
가상 센서도 `cam_pclk` 입력 클록이 필요하다. 실제 센서는 `SYNTHETIC=0`으로 선택한다.
독립 합성은 실제 입력 경로를 확인하기 위해 `SYNTHETIC=0`을 사용한다.

### 센서 수신 가정

- 8비트 병렬 DVP, RGB565 상위 바이트 먼저, 픽셀당 2바이트.
- PCLK 상승 에지에서 샘플링.
- HREF high일 때 유효 바이트, VSYNC high는 프레임 사이 blanking.
- VSYNC rising에서 직전 프레임의 결과를 확정하며, blanking은 최소 2 PCLK 이상.
- 기본 영상 320x240, 중앙 160x120 영역을 검출한다.
- RAW Bayer/YUV/반대 바이트 순서/다른 극성 센서는 변환·수정이 필요하다.
- **SCCB/I2C 초기화, 센서 XCLK 생성, RESET/PWDN 제어는 포함하지 않는다.**
  해당 핀의 극성과 설정값은 센서 모델을 알아야 작성할 수 있다.

ROI를 전부 받지 못한 프레임과 한 줄의 바이트 수가 홀수인 프레임은 검출에 사용하지 않는다.
이 검사는 ROI의 완전성을 보는 것이며, 센서 전체 해상도·모든 프로토콜 오류를 검증하는 장치는 아니다.
노란색 진입은 ROI의 35%, 이탈은 20% 기준이며 연속 3프레임을 요구한다.
밝기와 색 기준은 `card_detector.sv`에 모아 두었다. 실제 조명에서 조정해야 한다.

### 화면의 의미

- 위쪽 세 칸: 최근 프레임 수신 / ROI 완전성 / 카드 검출. 초록·노랑이 정상/활성이다.
- 가운데: 128x128 스프라이트를 2배 확대. 카드 검출 시 팔을 들고 혀를 내민 표정.
  4비트 팔레트, 두 프레임 합계 ROM 16KiB. `assets/sprite_preview.png`에서 원화를 확인할 수 있다.
- 아래 노란 막대: 노란 픽셀 수. 가로 1픽셀당 검출 픽셀 32개이며 백분율 표시는 아니다.
- 맨 아래 파란 비트열: 프레임 번호 하위 16비트, 왼쪽이 최하위 비트.
- LCD 120프레임 동안 새 입력 결과가 없으면 입력 정지로 판단해 기쁨 반응을 해제한다.
  대략적인 대기 시간은 실제 LCD 프레임 주기에 따라 달라진다.

외부 프레임버퍼는 사용하지 않는다. 색 통계만 계산하며 카메라 미리보기는 출력하지 않는다.
메일박스가 busy이면 해당 결과를 건너뛰고 다음 프레임 결과를 전달한다.
버퍼를 쌓는 구조가 아니므로 최신 결과가 전달되는 지연을 실물에서 측정해야 한다.

### LCD 가정

800x480, 수평 front/sync/back=40/48/168, 수직=13/3/29, HS/VS active-low.
픽셀 클록 33.333MHz 기준 약 60.1Hz를 가정한다. **강의 PDF에서 확정된 타이밍이 아니다.**
PDF의 p.71은 800x600, p.72는 800x480으로 충돌한다.
코어의 RGB·DE·HS·VS는 같은 2클록 파이프라인으로 정렬된다.
패널 DCLK 전달과 위상은 보드 wrapper에서 검증된 샘플링 에지에 맞춰 구성해야 한다.

### 자동 검증

- `tb_card_path.sv`: 실제 바이트 수신, 노란색/파란색 대조, 3프레임 안정화,
  잘못된 바이트 수, 불완전 ROI, 비동기 클록 메일박스 데이터 무결성.
- 같은 테스트에서 가상 센서부터 최상위 코어까지 연결하고,
  카메라 클록 정지 후 반응 해제와 재개 후 복구까지 확인한다.
- `tb_display.sv`: 두 표정의 800x480 PPM 생성, active 픽셀 수와 HS/VS 펄스 폭 확인.

## 실험 2: 조건반사 학습 회로

```text
학습 색 -> 감각 뉴런 A -> 가중치 A --+
                                   +-> 기대 반응 뉴런
대조 색 -> 감각 뉴런 B -> 가중치 B --+       ^
                                           먹이 교사 입력
```

`rtl/neuron/conditioning_top.sv`가 합성 대상이며 `model/reference.py`가 정수 기준 모델이다.
세 뉴런은 Izhikevich regular-spiking 파라미터 a=0.02, b=0.2, c=-65, d=8을
Q16.16으로 근사한다. explicit Euler로 이전 v/u에서 함께 갱신하고,
갱신한 v가 30 이상이면 reset을 적용한다. `dt=0.25ms`, 초기 v=-65, u=-13이다.
고정소수점 계수는 0.04=2621, a=1311, b=13107이며 우측 시프트는 산술 시프트다.

스파이크 출력, 감각 흔적과 시냅스 전류는 레지스터를 거친다.
이 한 단계 지연을 소프트웨어 모델에서도 동일하게 재현한다.
수치 보호 범위는 v/u 각각 [-120,120]이며 클리핑 발생은 시험 실패로 처리한다.
검증된 입력 범위 밖의 임의 전류에 대한 수치 안정성을 보장하지 않는다.

### 학습 규칙의 정확한 의미

- 감각 뉴런 스파이크 후 흔적을 2000단계(500ms) 유지한다.
- 먹이가 주어지고 학습 모드일 때, 출력 뉴런이 발화하면 최근 활성화된 감각 연결을 +1 강화한다.
- 가중치는 0~24로 제한한다. 감각 스파이크는 해당 가중치만큼 시냅스 전류를 추가한다.
- 시냅스 전류는 매 단계 1/64씩 감소하고 64에서 포화한다.
- **먹이 교사 입력으로 게이트된 인과적 연합 강화**이며 일반적인 양방향 STDP나 보상 학습은 아니다.
- 학습하지 않는 동안 가중치는 변하지 않는다. 소거·장기 저장은 구현하지 않는다.
- 초기화는 회로 전체 상태와 가중치를 초기화한다. 시험 단계에서는 뉴런 상태를 강제로 초기화하지 않는다.

현재 시험은 고정된 이상적 입력의 구성 가능성을 검증한다.
다양한 카드 제시 간격·노이즈·생물학적 타당성까지 검증한 결과는 아니다.
카드 검출 상태를 인간 조작 시간에 맞는 내부 전류/자극 지속시간으로 바꾸는 정책과
먹이 버튼 처리는 실제 통합 단계에서 결정한다.

### 자동 검증

학습 전 카드 단독 -> 8회 카드/먹이 짝짓기 -> 학습 중지 -> 카드 단독 ->
대조 색 -> 카드 재시험 순서로 총 39,600단계(모델 시간 9.9초)를 실행한다.
각 시험 구간은 200ms이다. 휴식 구간으로 잔류 전류와 감각 흔적의 영향을 줄인다.

출력: `reference.csv`, `conditioning_rtl.csv`, `conditioning_summary.json`.
39,600단계의 15개 상태값을 모두 정수로 비교한다. 학습 전후 반응, 대조 색,
가중치 고정, 수치 클리핑도 검사한다. 상태 변수의 비교가 실물 센서 성능을 뜻하지는 않는다.

`step_en`이 high인 클록 에지에서만 모델을 갱신한다.
시뮬레이션은 빠른 비교를 위해 매 클록 갱신하지만, 실제 구동에서는 0.25ms마다
1클록 폭의 enable을 만들어야 한다. 25MHz라면 6,250클록마다 한 번이다.

## 합성 결과 해석

`scripts/synthesize.tcl`은 board I/O를 제외한 out-of-context 합성이다.
카메라 24MHz, LCD 33.333MHz, 뉴런 25MHz의 내부 경로를 가정한다.
뉴런의 첫 50MHz 시도는 WNS -9.028ns로 실패했으며,
동일한 회로의 실험 클록을 25MHz로 낮췄다. 50MHz에서 사용하려면 별도 파이프라인
또는 정확한 enable 주기를 전제로 한 다중 주기 설계가 필요하다.
카메라/LCD 주파수는 실제 센서·패널에서 확정한 값이 아니다.
제어 신호의 첫 동기화 플롭만 false path로 처리하고,
메일박스 payload는 보유 레지스터부터 수신 레지스터까지 max-delay 25ns를 적용한다.
두 클록 전체를 false path로 숨기지 않는다.

`results/*_utilization.rpt`와 `*_synth_timing.rpt`를 확인한다.
합성 WNS는 배치·배선 전 추정이며, 보드 입출력 타이밍·CDC의 물리적 검증·
실제 동작 확인을 대신하지 않는다. 음수 WNS면 해당 클록 목표를 달성한 것으로 판단하지 않는다.

## 실물 연결 전 필요한 정보

`final.srcs/constrs_1/reference/board_pending.xdc`는 최초 검토 기록이다.
현재 활성 제약은 `final.srcs/constrs_1/new/hanback_lcd_pet.xdc`이며 LCD·버튼·학습용 보드 top에 적용한다.
카메라 실물 연결은 아래 정보가 추가로 필요하다.

1. 실제 모듈의 회로도/XDC, I/O bank 전압.
2. CMOS 센서 모델, 설정 예제, XCLK·PCLK·HREF·VSYNC·데이터 핀.
3. TFT 패널 모델 또는 실제 동작하는 예제의 타이밍·클록 위상.

확보 후 보드 wrapper와 센서 초기화를 작성하고, 타이밍·핀 제약을 적용해
구현/bitstream/실물 시험으로 진행한다. 보드 핀·센서 설정을 임의로 넣은 파일은 제공하지 않는다.
